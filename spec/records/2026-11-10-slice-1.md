## Failure accounting and corrections

The initial 17-story run had 5 failures: filtered records could stay inside
collapsed Kanban lanes and dialog assertions preceded transition completion.
Selecting the first populated anchor and awaiting visible/removed modal state
reduced this to 3, then 0 on the exact affected journeys.

Adding the shared profile menu and Command View initially produced 5 startup
failures in the focused 19-story catalog. One installed Svelte version was
confirmed; explicit host runtime deduplication and initial dependency
optimization fixed the split-runtime/reload startup failure. Cold runs pass.

The next focused run exposed 2 failures around popup transition/landmark
semantics, followed by accessible-name mismatches. The nested introductory
header was removed, popup teardown is awaited, the repository trigger includes
its visible label, and the command root names its input correctly. The exact
repository-picker target went from 1 failure to 0. No rules or assertions were
disabled. A later type check caught 1 unsupported Testing Library query option;
removing that option preserves its default exact-name match.

Final functional, interaction and accessibility failures are zero. Native
browser tooling treats Kanban's drag-disabled cards as disabled for automatic
pointer actionability; inspection used explicit activation, while the governed
stories prove card opening and keyboard selection. This inherited Design Core
0.12.3 behavior has no consumer override and remains a source-level follow-up.
