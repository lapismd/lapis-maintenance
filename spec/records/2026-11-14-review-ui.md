# R1 Storybook review UI — 2026-11-14

The revised plan and canonical foundation were committed as `43937e60` before
UI implementation. R1 adds local production presentation and a review controller
under `src/components/maintenance-review` and `src/maintenance/review`, mounted
only by disposable fixture hosts in `catalog/review`. The live App, GitHub
adapters/policies, caches, session, routing, dependencies and sibling packages
are unchanged. R2–R4 remain planned and require separate approval.

## Delivered preview

- The existing shell, board and joined inspector lead into a main-panel PR
  workspace. Back retains board filters and selection. Overview, Checks,
  Activity and Files reuse the same local components as standalone stories.
- Checks retain grouping/disclosure, linked jobs, float/dock and merge controls.
  Activity supports pagination. Files support search, selection, unified/split
  public diff rendering, cached patches, binary and oversized explanations.
- Simulated PR approval/merge, fork workflow approval and environment review
  identify the revision/run/attempt/environment before explicit confirmation.
  Examples include eligibility checking, reviewer/timer waits, denied access,
  accepted, rejected stale targets and uncertain results without replay.
- Ports own effects; the controller rejects stale responses, retains resource
  data during refresh and loads Activity/Files lazily. No fixture action writes
  to GitHub, accesses credentials or persists data. No T3 code was copied.

The first unit run found 2 fixture initialization failures; moving fixture Map
creation into the constructor restored the same target to 8/8. Initial type
checking found 8 unsupported Storybook query options; anchored accessible names
replaced them. The architecture audit found a 310-line stylesheet; splitting
activity styling by responsibility restored the 300-line budget.

The first cold Storybook run had 16 failures and 32 unhandled errors after Vite
optimized newly used public diff/tabs entries mid-run. Prebundling those entries
in Storybook and its test project removed the runtime reload failures without
changing live startup. The next exact run reached all 40 original cases with
6 failures: dialog closing lifetime, dark count contrast, a missing semantic
heading and entrance-animation assertions. Corrections reduced this to one
duplicate feedback query, then 40/40. Expanded coverage found one transition
timing failure between review and merge; waiting for the closing modal to leave
the DOM restored 52/52. No assertion, accessibility rule or timeout was weakened.
The first final specification run passed validation, book and architecture but
flagged the missing mapped controller chapter; documenting the R1 boundary in
that chapter satisfied the mapping, then an atomic-acceptance warning was fixed by folding the new boundary into its existing single-sentence bullet; the same checks pass without rule changes.
After aligning the initial board selection and failed/running fixture details,
the exact 52-case lane exposed one narrow-file-list accessible-name failure;
supplemental file state/statistics now form the accessible description while
the visible file path remains the button name, preserving voice activation.
The final type pass rejected `aria-description` in the published Button's HTML
types; standard `aria-describedby` with a host-local description ID replaced it.

Local logs are ignored under `.local/review-*.log`. Screenshot comparisons and
baseline updates were not run; stories remain `visual-pending`.
